## 0. 关键结论（先看这个）

**当前部署的 new-api 版本已原生支持"模型元数据"，研发无需新建表或开发新功能。**

从线上前端代码（`web/src/features/pricing/types.ts` 的 `PricingModel` 类型）确认，`/api/pricing` 已预留以下字段，管理后台「模型元数据」录入后即会在广场卡片和详情弹窗中直接展示：

| 原生字段 | 含义 | 当前 3 个模型状态 |
|---|---|---|
| `description` | 模型描述（卡片 + 详情展示） | ❌ 未录入（所以线上卡片没有简介） |
| `tags` | 模型标签（卡片展示前 2 个 + "+N"） | ❌ 未录入 |
| `context_length` | 上下文长度（详情"Context"） | ❌ 未录入 |
| `max_output_tokens` | 最大输出（详情"Max output"） | ❌ 未录入 |
| `parameter_count` | 参数量（详情"Parameters"） | ❌ 未录入 |
| `release_date` | 发布时间（详情"Released"） | ❌ 未录入 |
| `knowledge_cutoff` | 知识截止（详情"Knowledge cutoff"） | ❌ 未录入（可选） |
| `input_modalities` / `output_modalities` | 输入/输出模态：`text / image / audio / video / file` | ❌ 未录入 |
| `capabilities` | 能力枚举，见 §3 映射表 | ❌ 未录入 |
| `supported_endpoint_types` | 支持端点（详情"Endpoints"） | ✅ 已配置 |
| `enable_groups` / `group_ratio` | 可用分组与分组倍率（详情"Groups"） | ✅ 已配置 |
| `vendor_id` / `vendor_name` / `vendor_icon` | 厂商信息（卡片图标 + 详情"Provider"） | ✅ 已配置（deepseek 缺 icon） |

**主要工作量 = 在管理后台为 3 个模型补录元数据（运营操作，零开发）。** 仅"备案信息、评测分数"等少数展示需要二次开发（见 §5）。

## 1. 现状盘点

线上 3 个模型（`GET /api/pricing`）：

| 模型 | 厂商 | 支持端点 | 输入倍率 | 补全倍率 | 缓存倍率 |
|---|---|---|---|---|---|
| `deepseek-v4.1-flash` | DeepSeek | openai | 0.142857 | 4.0 | 0.02 |
| `GLM-5.3` | 智谱 | openai / anthropic / openai-response | 0.571429 | 3.5 | 0.25 |
| `GLM-5.3-Flash` | 智谱 | openai / anthropic / openai-response | 0.057143 | 3.5 | 0.2875 |

**价格换算口径**：new-api 倍率体系 `model_ratio 1 = $2 / M tokens`。
- 输入价 = `model_ratio × 2`；输出价 = `输入价 × completion_ratio`；缓存命中价 = `输入价 × cache_ratio`
- 按 1 USD ≈ ¥7 展示：三款模型分别为 **输入 ¥2 / ¥8 / ¥0.8 每百万 tokens**，输出 ¥8 / ¥28 / ¥2.8，缓存 ¥0.04 / ¥2 / ¥0.23

## 2. 需要补录的内容（附现成文案）

### 2.1 description（模型描述）

写作公式（参考硅基流动）：**一句话定位（系列 + 定位 + 参数/上下文）→ 架构与技术 → 能力亮点 → 适用场景**，一段式 80–200 字；卡片只显示前 2 行，前 40 字必须独立成立。

三个模型的标准文案（已写入原型，可直接粘贴到后台）：

1. **deepseek-v4.1-flash**：DeepSeek-V4.1-Flash 是 DeepSeek-V4 系列中的轻量 MoE 语言模型，总参数量 284B、激活参数量 13B，支持 1M tokens 超长上下文与最高 384K tokens 输出。模型采用 CSA 与 HCA 混合注意力架构，引入流形约束超连接（mHC）与 DSpark 推测解码，显著提升长上下文推理效率；V4.1 版本针对智能体与编程能力进行后训练强化，原生支持 OpenAI Responses API 与 Codex 适配，reasoning_effort 支持 low / high / max 三档调节，适用于复杂 Agent 工作流、长文本理解与代码任务。
2. **GLM-5.3**：GLM-5.3 是智谱 AI 推出的 GLM-5 系列旗舰模型，沿用与 GLM-5.2 相同的基础模型，通过后训练在复杂编码、网络安全和长程智能体任务上实现显著提升。模型采用 MoE 架构，总参数量约 744B、激活参数约 40B，原生支持 1M tokens 上下文窗口、函数调用与结构化输出，适用于复杂软件工程、漏洞发现与长程智能体任务。
3. **GLM-5.3-Flash**：GLM-5.3-Flash 是智谱推出的原生多模态模型，总参数 320B、激活参数 18B，采用稀疏注意力与线性注意力混合架构，支持 1M 上下文，擅长视觉理解、编程、深度推理与复杂智能体任务。

## 3. capabilities 能力枚举 → 前端展示映射

`capabilities` 为后端枚举（前端原生支持），建议录入值：

| 枚举值 | 前端展示建议 | deepseek-v4.1-flash | GLM-5.3 | GLM-5.3-Flash |
|---|---|---|---|---|
| `function_calling` | 🛠️ 工具调用 | ✅ | ✅ | ✅ |
| `structured_output` | 🧩 结构化输出 | ✅ | ✅ | ✅ |
| `reasoning` | 🧠 深度推理 | ✅ | ✅ | ✅ |
| `vision` | 👁️ 视觉输入 | — | — | ✅ |
| `streaming` | ⚡ 流式输出 | ✅ | ✅ | ✅ |

另有原生枚举 `tools / json_mode / system_prompt / web_search / code_interpreter` 可按需启用。
端点能力（Responses / Anthropic 兼容）不需要录 capabilities——前端会按 `supported_endpoint_types` 在详情页"Endpoints"单独展示。

## 4. 原型对齐说明（本次已裁剪）

`model-square-v2.html` 已按 kerapi.cn/square 线上结构裁剪，**删除了线上没有的模块**：

- ❌ 在线体验（playground 模拟对话）

- ❌ 模型备案信息面板

保留/对齐线上的部分：Hero 文案（"主流模型，尽在模型广场"）、搜索与热门模型 chips、类型/系列/能力标签筛选、排序、卡片（厂商图标 + 名称 + 描述 + 标签 + 价格）、详情抽屉（简介 / 规格 / 价格明细 / 支持的 API / API 调用示例）。新增展示均可映射到 §0 的原生字段。
